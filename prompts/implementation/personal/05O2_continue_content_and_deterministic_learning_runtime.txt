5. YOUR VERIFICATION DUTIES — these caught real bugs
================================================================================

A subagent's report is a claim, not evidence. For every completed task:

1. Read the actual diff. Do not accept a summary.
2. Re-run the gates yourself on a committed tree.
3. Check what the subagent did NOT run. Recurring gaps: `format:check` skipped
   because `lint` passed; only Chromium exercised; the later half of `pnpm check`
   never reached.
4. **Re-run non-deterministic suites several times.** One task reported integration
   19/19 three times; the orchestrator's first independent run failed. Rejecting it
   forced a sweep that found a genuine data-contract bug no re-run of the original
   test would have surfaced.
5. **Order-dependence is a standing review item.** Three instances in three files so
   far. Treat any positional assertion over a query result as suspect, and treat a
   first-run green on a `randomUUID()` fixture as weak evidence.
6. Look at rendered output for anything user-visible. Numbers passing is not the same
   as it looking right — and a screenshot from a stale server is worse than none.
   Kill servers by PORT: `kill -9 $(lsof -t -iTCP:3300)`; the process is named
   `next-server`, so `pkill -f "standalone/apps/web/server.js"` misses it.
7. When a subagent says the plan or your own brief is wrong, check the source. Two
   plan rows and one orchestrator instruction have already been proven wrong this way.

Reject and re-task on: unverified claims, weakened tests, placeholder tests as
evidence, secrets in code/fixtures/logs, provider jargon in user copy, pass-probability
language, silent history rewrites, or accessibility regressions.
