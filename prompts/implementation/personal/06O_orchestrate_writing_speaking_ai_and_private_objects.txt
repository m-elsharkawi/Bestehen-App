================================================================================

Default to deterministic fakes and generated test media. Do not use the owner's voice, drafts,
account content, credentials, or personal objects as fixtures. Do not sign in to provider consoles

Live-provider work is disabled unless ALL of these already exist:

- a configured spend envelope and circuit breaker;
- approved region, data terms, retention, and release-registry pins;
- a redacted benchmark protocol with a stop condition; and
- explicit confirmation from the owner for the billable run.

Absence of a live run is not a defect. Record it as "not run: owner gate or spend authorization not
present." Never invent benchmark results, provider receipts, deletion confirmations, or quality
scores.

The accepted plan must still define admission criteria for the named candidates in 06P: Gemini 3.6
Flash, OpenAI mini Transcribe/TTS, and batch-audited Polly media. Treat those names as candidates,
not approvals. Reconfirm official identifiers and availability before any authorized live run.

Every subagent must preserve these invariants:

- model output is a version-pinned candidate, never canonical evidence by itself;
- application validation and explicit application acceptance are separate, durable steps;
- model confidence never becomes readiness truth or pass probability;
- deterministic precheck runs before a productive provider call;
- one structured candidate and at most one justified escalation are allowed;
- billable paths fail closed when no spend envelope is configured;
- provider aliases cannot silently change a release;
- provider payloads contain only the minimum data required for the capability;
- raw audio never enters offline sync or export;
- raw audio is deleted immediately after the accepted derivative and no later than seven days;
- failed or pending deletion and provider purge status are observable and described honestly;
- logs, traces, receipts, errors, and fixtures contain no secrets or productive content; and
- private-object authorization fails closed.

Cost pressure may select a cached, deterministic, fixed-media, queued, or explicitly lower-claim
fallback. It may not erase productive Writing or Oral evidence or relabel an unevaluated result as
evaluated.

================================================================================

Stage 06 Planning must be accepted before any Execution task starts. Planning changes no
production code, calls no paid model, uploads no recording, and mutates no provider state.

You choose the split. Use these rules:

- Split by contract seam, not by file count.
- Give one subagent end-to-end ownership of a seam: schema, domain behavior, adapter boundary,
  migrations, tests, and evidence.
- Keep one integrating planner responsible for a single coherent `plan.md`. Planning research may
  be delegated, but do not assemble contradictory mini-plans.
- Sequence tasks that touch shared schemas, attempt/evidence contracts, job tables, app shells, or
  the same UI files. Parallelize only when file and contract boundaries are genuinely disjoint.
- Require each subagent to state its expected file set before editing. Reject unexplained edits
  outside it.
- Give every subagent the exact baseline SHA, local-main rule, CI restriction, cleanup rules,
  applicable owner gates, and a testable Definition of Done.
- Decide whether each subagent commits or leaves changes for review. Only one dirty-tree task may
  run at a time. Never let multiple agents edit the same checkout concurrently.
- Forbid subagents from pushing, opening PRs, using productive credentials, editing Design source,
  weakening tests, or changing another stage's accepted plan.

8. MODEL SELECTION - capability first, cost second
================================================================================

Do not choose the strongest model by default. Choose the least expensive model that can make the
required judgment safely, then give it a narrow brief.

Use the strongest reasoning tier for:

- the integrated Stage 06 plan;
- shared schema and state-machine design;
- candidate validation and application-acceptance semantics;
- idempotency, cancellation, and late-result correctness;
- privacy, authorization, raw-audio deletion, and security-sensitive review; and
- resolving contradictions between architecture, accepted handoffs, provider constraints, and
  Design behavior.

Use a reliable mid-tier coding model for:

- implementation against already accepted contracts;
- deterministic adapters and fakes;
- migrations with an established repository pattern;
- Writing and Speaking UI states after behavior is fixed;
- provider contract tests, browser tests, fixtures, and integration wiring; and
- targeted bug fixes returned by orchestrator review.

Use a fast lower-cost model only for tightly mechanical work:

- fixture expansion from an exact matrix;
- generated manifests and traceability updates;
- documentation tables from verified evidence; and
- repetitive test-case scaffolding whose assertions are specified in full.

Do not assign a lower-cost model to invent security, privacy, concurrency, evidence, cost, or
deletion semantics. A cheap subagent may transcribe verified results, but it may not decide them.

Record every subagent's task, selected model/tier, reason for that selection, baseline SHA, commits,
and verification result in the handoff. If an agent stops partway, inspect its diff and tests before
resuming or replacing it. Do not pay a second agent to rediscover work that can be safely completed
from the existing evidence.
